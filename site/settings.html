Settings screen

Settings and sync

Set editing defaults and connect to UPbDB when you need it.

Spot and outline defaults

Set the naming pattern with {sample}, {grain}, {n} or a zero-padded form such as {n:03}. Edit diameter presets and the default diameter in µm, snapping and the active spot colour.

Under Outlines, set a margin in µm and choose whether to smooth new outlines. These settings apply to outlines found or drawn from now on; existing outlines stay as they are.

Sign in to UPbDB

  1. Enter the server address under UPbDB → Server.
  2. In the standalone desktop app, choose Sign in…. The server’s sign-in page opens in your browser.
  3. Finish with any method the server offers. The browser hands a one-time code back to the app.

A pasted token also works. Choose whether to remember it on this computer or keep it only until the tab closes. A static browser build uses token entry; hosted in UPb Lab, GrainAtlas uses the shell’s sign-in.

The server is optional. Leave it empty to work locally.

Read the sync chip

The top-bar chip compares the project with the database. Click it for details about local and database changes, the base revision and the last sync. Its adjacent action follows the current state.

StateChip textWhat to do
checkingChecking database…Wait for the database check.
unregisteredNot in the databaseChoose Register… and pick an existing mount. Create mounts in UPbDB.
in-syncIn sync · v… r…The project’s elements match the checked database revision.
local-changesLocal changes · … / Not yet synced · …Choose Sync to database. Counts describe changed grains, spots and labels.
server-newerDatabase is newerChoose Update from database.
both-changedBoth changed / Database has moreReview differences, or sync to keep database additions. Conflicting elements need a choice.
offlineOffline, changes kept hereWork locally, then Retry when the server is available.
needs-confirmationNeeds confirmationReview the proposed grain retirements and spot deletions before continuing.

New images not published is added when the mosaic images changed. Element changes and images are saved separately; choose whether to publish a new atlas version when syncing. Even with elements in sync, unpublished images keep the action available.

Other messages can take priority: Read-only access, Sync failed, This project is linked to another mount, or a count of items held back. Details explain the problem. A draft held on this computer is marked Your draft here, with its base revision or a note that the base has not been checked.

For conflicting elements, choose Mine, Theirs or, where offered, Both to keep a separate copy. Other changes combine automatically. Sync to the database when saving runs only for registered projects when the server is reachable and editing is allowed.

Published atlases and results

Choose lossless or near-lossless WebP atlas tiles and set the package root on lab storage. Bundles record the package path and content hash; the raw package is never uploaded. Publishing sends the atlas images and project elements.

Enter a project id and choose Open from server to read a published atlas. It opens read-only; Edit a copy creates a local copy. A linked mount supplies results on spots; results are not saved in the project.

Appearance and updates

Choose Light, Dark or System. The image surface stays dark in both themes. Hosted copies follow the shell’s theme. Reset layout restores panel positions and folded panels. See Install for the Updates controls.
