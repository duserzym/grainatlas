Command line

Batch and export work

Use the Rust command line for repeatable processing of local packages.

Run from a source checkout with cargo run --release -p grainatlas-cli --, followed by a command. With an installed CLI binary, start with grainatlas. Use --help on a command for its full options.

Commands

CommandPurpose
stitchStitch an area or all areas of a package into a project folder.
sheetsRe-render print sheets from saved mosaics and grains; whole-area output is also available.
batchStitch each direct package folder and continue after failures.
infoList the areas and tiles of a package without stitching.
segmentSegment saved areas using their saved placements, parameters and manual decisions.
rerenderRe-run correction, blend and tone from saved placements without stitching or segmenting.
import-grainsCopy saved grains from another copy of the same project into areas without grains, and re-link spots.
overlayList a printout photo and initialize its area overlay.
renderStack saved mosaics with grain outlines for visual checking.
checkReport saved-project warnings; warnings exit successfully.
atlasStitch a package, find grains, apply Auto tone and write an atlas folder or zip.
atlas-projectWrite an atlas zip from a saved project, preserving its grains, spots and labels.
hashPrint base and Auto-plus-grain-tone mosaic hashes for native/browser parity checks.
photometryCompare correction parameter sets and write reduced Auto-toned mosaics with overlap reports.

Stitch and print

cargo run --release -p grainatlas-cli -- stitch <package-or-area-folder> --out <name>.grainatlas --auto --polarity both --print tabloid

--print tabloid makes context-first sheets with each owned grain printed once. Scale is chosen from grain sizes, targeting a median grain about 15 mm on paper; --scale 8 fixes 1 mm of paper to 8 µm of sample. --print-style grains requests the older single-grain crop layout.

grainatlas sheets <name>.grainatlas --out <dir>

The output directory must be outside the saved project folder. Use --svg for individual pages as well as the PDF, registration and sheet statistics.

Find missing grains

grainatlas segment <project> --missing
grainatlas segment <project> --add-missing [--area ID]... [--signal auto|cl|bse] [--dry-run]

--missing processes areas without a saved grain entry. --add-missing needs an existing grain list and adds uncovered detections while preserving outlines, numbers and spot links. The two flags cannot be combined.

Re-render saved areas

grainatlas rerender <project.grainatlas> [--area ID]... [--background keep|on|off] [--dry-run]

Save and close the project first. The original package must remain at its saved path. The command keeps geometry, grains, spots and annotations, and backs up the project record and selected mosaics before replacement. Reopen the project after it finishes.

--dry-run computes a JSON report without writing. With no area flag, areas without saved placements are skipped; explicitly selecting one is an error. See the README recovery instructions before recovering an interrupted replacement.

Export an atlas

grainatlas atlas <package> --out <dir-or-archive.zip>

To export an existing project with its saved decisions, use atlas-project instead.

Desktop launch arguments

These are arguments for the desktop app, separate from the CLI subcommands:

grainatlas <package-or-area-folder> [--stitch] [--segment]
grainatlas <images…> --um-per-px <µm> | --field-um <µm> [--stitch]
open -a grainatlas --args A.grainatlas B.grainatlas C.gaproj --stitch

Several folders open as separate tabs. Saved .grainatlas folders and .gaproj files also open directly.
